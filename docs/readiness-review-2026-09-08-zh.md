# CC Switch 可用性检查与修复（2026-09-08）

## 范围与结论

核心工程是 `cc-switch-proxy-api`，其余目录作为参考项目，本轮没有改动。
开始检查时已有的 15 个未提交修改文件被保留，没有执行 Git reset、提交或推送。

修复前不宜把“已有页面、可以编译”当作功能完成：签到缺后端调度、代理池配置不持久化、订阅不自动更新，网关还存在轮询和接线错误。本轮修复的是本机 Rust 网关、API Key 轮询、公益站签到与 HTTP/SOCKS 代理池的实际执行链。

这不是对 CLIProxyAPI 所有功能的完整等价认证。OAuth 多账号轮询、所有机场协议、所有模型和真实第三方网站的兼容性不在已验证范围内。

## 修复清单

| 模块 | 原有问题 | 修复方式 |
|---|---|---|
| API Key 轮询 | 秒级时间戳相同，连续请求重复选择同一 key；在途请求未完成前轮询不前进 | SQLite 连接锁内完成选线和首选 key 预占，使用单调毫秒排序标记；预览保持只读 |
| 网关降级 | 旧供应商的自动故障转移开关关闭时，新网关也只能试一把 key | 网关独立启用重试和超时，仍尊重每应用的 `max_retries` 上限 |
| 路由边界 | key 全部冷却/失效、模型不匹配时回落旧账号 | 区分未配置与不可用；配置中的网关不可用返回错误，不越界选择旧账号 |
| OpenAI / DeepSeek | 接入点可添加，但没有消费它们的请求路由 | 接入 Codex 协议族；标记 Chat wire format，复用 Responses → Chat 转换 |
| Gemini | 选线之后才从 URI 提取模型 | 选线前解析 URI 模型，保留原请求的会话信息 |
| 兼容性重试 | 图片/签名/budget 重试成功绕过网关记账，还可能触发供应商切换 | 四条成功路径统一记账，不写 synthetic provider 的旧健康表，不切换托盘供应商 |
| key 判罚 | 较晚的瞬时失败清掉硬状态，较晚成功清掉新冷却 | 硬状态与冷却只能保留/加重，或由明确恢复操作解除 |
| 429 | Gemini 普通 `RESOURCE_EXHAUSTED` 被永久标成余额耗尽；响应头丢失 | 模糊配额错误暂时冷却；保留 `Retry-After`，支持秒数、HTTP-date 与上限 |
| 代理池配置 | 开关、TTL、超时等重启后重置 | 保存到 `settings.proxy_pool_config` 并在启动恢复，后端校验范围及 URL |
| 订阅 | 更新间隔没有执行入口；重新启用不恢复；在途刷新可复活停用项 | 后台维护循环自动刷新；重新启用重建节点；提交前核对订阅版本与状态 |
| 出站代理 | 真实请求未反馈节点健康；构建节点客户端失败却改用其它出口 | 记录实际传输结果，407/传输失败驱动熔断；客户端创建失败显式返回 |
| 节点生命周期 | 节点撤下后连接缓存仍保留；半开失败不重新冷却 | 移除/熔断/重置时回收对应缓存；失败重新计冷却 |
| 代理地址 | IPv6 未加方括号；`socks5h` 丢掉远程 DNS 语义 | 正确生成 IPv6 URL，池中 SOCKS 请求统一由出口解析目标域名 |
| 探测 | 读完整错误页才检查长度；延迟探测地址未使用 | 有界读取并检查回显 IP；可单独探测延迟目标，共享单节点超时预算 |
| 自动签到 | 只保存定时设置，没有后台调度 | Rust 启动注册 30 秒检查循环，按本地日期去重，启动/唤醒后补执行今日任务 |
| 签到状态 | 默认小时错误地为 0；读体失败被当成空体成功；500 也能匹配成功串 | 默认 9 点；传播读体错误；要求 HTTP 2xx；读取上限 256 KiB |
| 签到认证 | 登录重定向丢 Cookie；多份 Cookie/UA 冲突 | 保留登录响应 Cookie，合并 Cookie，浏览器凭证固定配套 UA |
| 并发与退出 | 手动/自动任务可重叠，配置 read-modify-write 丢更新，取消留下隐藏窗口 | 执行锁、配置写锁和 RAII 窗口清理；退出中止调度 |
| 可操作性 | API 页面没有服务入口、地址不明确 | 新增网关启动与实际 Base URL 展示；展示自动签到条件及最近执行日期 |
| 测试隔离 | Windows 兼容路径会绕过 `CC_SWITCH_TEST_HOME` 访问真实目录 | 显式测试目录优先于自定义路径和旧 HOME 回退，增加隔离回归测试 |

## 使用顺序

### API 网关与轮询

1. 打开“API 接入”，添加正确协议的上游基础地址和 API Key。
2. 同一优先级参与 LRU 轮换；数字越小越优先。展示拖拽顺序不改变路由优先级。
3. OpenAI / DeepSeek 是 Chat Completions 上游；Codex 是原生 Responses 上游；Claude、Gemini 分别使用原生协议。
4. 点击“启动网关”，把客户端 Base URL 配置成页面实际显示的地址。该按钮只启动服务，不偷偷改写 CLI 配置。
5. 如需原有自动接管 CLI 配置，仍从原有代理/接管入口操作。
6. 请求最多尝试 `max_retries + 1` 条线路。400 等请求错误不会通过遍历全部 key 来掩盖。
7. 401/明确余额耗尽等硬状态，需要修正密钥/充值后“恢复可用”；普通限流在冷却到期后重新参与。

默认监听 `127.0.0.1:15721`，以界面显示的实际配置为准。独立网关的局域网入站鉴权未在本轮新增，不把本机验证等同于可公开暴露的服务。

### 自动签到 / 开机自启

1. 配置站点请求、认证与成功判定条件，先手动运行确认站点返回的实际结果。
2. 打开“每日自动签到”，选择本地时间的小时。
3. 若希望开机后运行，在原有设置中启用开机自启；需要关闭窗口后仍执行时，启用关闭到托盘。
4. 应用未运行、电脑关机/休眠时不会执行。再次启动/唤醒后，如果已过设定时间，补执行当日任务，不追补过去多日。
5. 同一天批次只自动执行一次；失败可手动重试。中途退出后，已成功站点通过自身成功日期避免重复，未完成站点可以继续。

Browser 方式现已采用每条条目独立的浏览器 profile：保存条目后打开对应登录窗口，完成登录并关闭窗口，签到会从该条目读取账号 Cookie；显式请求头仍优先。完整用法、原生验证和兼容边界见 [方案 B](./checkin-browser-profiles-zh.md)。Cookie/UA 并不保证所有 Cloudflare 策略都会接受 Rust 请求，真实站点仍需按实际响应验收。签到不随代理池轮换出口，避免验证 Cookie 绑定的 IP 漂移。

Browser 多账号串号的追加修复及先失败后通过的验证记录见 [方案 A 修复记录](./checkin-browser-cookie-fix-2026-09-08-zh.md)。

### 代理池

1. 添加 HTTP / HTTPS / SOCKS5 节点，或对应格式的远程订阅，先手动探测。
2. 开启池总开关，配置会持久化；远程订阅刷新间隔设 0 表示不自动刷新。
3. 同一 key/provider 使用粘性租约，节点失败后换出口；401/429 是上游账号结果，不误罚出口节点。
4. 主动探测间隔设 0 不会关闭订阅自动刷新。后台维护检查的粒度为 30 秒。
5. 出口回显地址应返回纯 IPv4/IPv6 文本；延迟地址可以留空，留空时复用出口探测耗时。

代理池未启用或无可用节点时，沿用已有全局/系统代理配置；当前不是“只允许从池出站”的严格模式。这与 API Key 全部不可用时不回落旧账号，是两个不同层面的规则。

`vmess/vless/trojan/ss/hysteria` 等不是 reqwest 原生代理协议，导入时仍跳过并报告，不能直接把这类机场订阅当作已可用的 HTTP/SOCKS 出口。
